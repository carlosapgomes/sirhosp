# Runbook de Upgrade — v0.1.0-rc.35 (2026-10-10)

## Escopo

Esta release entrega três changes desde a `v0.1.0-rc.34`:

1. `add-dev-browser-verification-suite` (arquivada em 2026-10-09) —
   tooling **dev-only** de verificação do portal (sessões efêmeras com
   revogação, driver smoke real por browser headless, skill MCP
   `verify-sirhosp`). Nada deste item é instalado no hospital; nenhum
   comportamento de produção muda por ele.
2. `externalize-verification-origins` (ORIG-001) — idem: somente tooling
   dev (resolvedor de origens privadas, fixtures sintéticas, runbook/skill).
   Nenhum comportamento de produção muda por ele.
3. `statistics-export-zip-per-sector` (ZIP-001) — **única mudança de runtime
   desta release, BREAKING**: `GET /statistics/export/` passa a servir um
   ZIP com um XLSX por setor (`estatisticas-diarias-{YYYY-MM-DD}-r{N}.zip`;
   internos `...-{slug}.xlsx` em `snake_case` ASCII), em vez do workbook
   único com uma aba por setor. Conteúdo por setor preservado (7 seções,
   colunas, ordenação, anti-fórmula). Auditoria passa a registrar
   `file_count` (migration `0006`, backfill `1` nas linhas legadas) e
   `help_texts` atualizados (migration `0007`, sem efeito de schema).

Base do upgrade: **v0.1.0-rc.34**.

O intervalo `v0.1.0-rc.34..rc.35` não altera Compose, Dockerfile, `deploy/`
nem units: os assets de runtime são **byte a byte idênticos aos da rc.34**.
Só a imagem muda (código + migrations `0006`/`0007`).

Validação anterior à tag:

- `./scripts/test-in-container.sh quality-gate` (check, unit 4194, ruff,
  mypy 454 arquivos) — exit 0;
- `./scripts/test-in-container.sh integration` — 949 aprovados, exit 0, com
  as migrations aplicadas;
- `uv run python manage.py makemigrations --check --dry-run` — "No changes
  detected";
- `./scripts/markdown-lint.sh` nos docs novos — sem erros;
- `openspec validate --specs --strict` — 58 specs aprovadas;
- workflow de publicação reexecuta o quality gate oficial sobre a tag exata
  antes de buildar.

## Impacto operacional

- Duas migrations aplicadas por `migrate --noinput` (`0006` com backfill,
  `0007` no-op de schema). Diferente da rc.34, o `migrate` **não** é no-op.
- Nenhuma variável de ambiente nova, nenhuma credencial nova, nenhuma
  permissão nova.
- Nenhuma alteração em materialização, pipeline adaptativo, workers, timers,
  units ou Compose.
- Rollback code-only seguro: a coluna extra `file_count` é ignorada pelo
  código da rc.34; sem restauração de banco para rollback de imagem.

## Pré-condições

1. Confirmar a versão atual (`v0.1.0-rc.34`) sem imprimir outras variáveis
   do `.env`.
2. Confirmar PostgreSQL saudável.
3. Registrar a escala atual de `persistent_worker`; o baseline hospitalar é de
   10 réplicas.
4. Parar temporariamente os produtores de novos ciclos (`census_orchestrator`
   e `sirhosp-stale-reconciliation.timer`), mantendo os workers ativos para
   drenar a fila.
5. Aguardar `IngestionRun` sem itens `queued` ou `running` e nenhum batch de
   censo aberto (mesma checagem de drenagem da seção 5c do `deploy/README.md`).
6. Baixar da release imutável o Compose, os units e este runbook.
7. Criar backup PostgreSQL em formato custom, confirmar arquivo não vazio e
   validar o catálogo com `pg_restore --list`.
8. Confirmar que os três timers de fallback (`sirhosp-discharges.timer`,
   `sirhosp-historical-recovery.timer` e `sirhosp-daily-statistics.timer`)
   estão `disabled` e `inactive`.

## Pausa e drenagem

No host hospitalar, como `root`, em `/srv/apps/prisma`:

```bash
systemctl stop sirhosp-stale-reconciliation.timer
docker compose --env-file .env -f compose.hospital.yml stop census_orchestrator
```

Confirme a drenagem antes de recriar os workers:

```bash
drain_state="$(
  docker compose --env-file .env -f compose.hospital.yml exec -T web \
    uv run --no-sync python -c \
    'import os,django; os.environ.setdefault("DJANGO_SETTINGS_MODULE","config.settings"); django.setup(); from apps.ingestion.models import IngestionRun,CensusExecutionBatch; print(IngestionRun.objects.filter(status__in=("queued","running")).count(), CensusExecutionBatch.objects.filter(status="running").count())'
)"
printf 'drain_state=%s\n' "$drain_state"
test "$drain_state" = "0 0"
```

Se ainda houver itens ativos, aguarde com os 10 workers em execução. Não
reinicie containers durante a drenagem.

## Download e backup

```bash
set -euo pipefail
export OLD_VERSION=v0.1.0-rc.34
export NEW_VERSION=v0.1.0-rc.35
export COMPOSE_FILE=compose.hospital.yml
cd /srv/apps/prisma

mkdir -p backups deploy/systemd
chmod 700 backups

curl -fL --retry 3 -o "${NEW_VERSION}-upgrade.md.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${NEW_VERSION}-upgrade.md"
curl -fL --retry 3 -o "${COMPOSE_FILE}.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${COMPOSE_FILE}"

# Assets de runtime idênticos aos da rc.34; instalados da MESMA tag da
# imagem para manter a procedência byte a byte.
curl -fL --retry 3 -o deploy/exit-reconciliation-scheduler.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/exit-reconciliation-scheduler.sh"
curl -fL --retry 3 -o deploy/daily-statistics-activation-preflight.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/daily-statistics-activation-preflight.sh"
chmod +x deploy/exit-reconciliation-scheduler.sh deploy/daily-statistics-activation-preflight.sh
for unit in \
  sirhosp-discharges.service sirhosp-discharges.timer \
  sirhosp-historical-recovery.service sirhosp-historical-recovery.timer \
  sirhosp-stale-reconciliation.service sirhosp-stale-reconciliation.timer \
  sirhosp-daily-statistics.service sirhosp-daily-statistics.timer; do
  curl -fL --retry 3 -o "deploy/systemd/${unit}" \
    "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${unit}"
done

sha256sum "${COMPOSE_FILE}.new"
# Compose idêntico ao da rc.34; confira contra o hash registrado na rc.34
# (cd0e444c9316a8b267823f31cf1d4a1fee40e7bf2b96b9aa27da10002f4f9dc1)
# antes de prosseguir.
cp -p "$COMPOSE_FILE" "${COMPOSE_FILE}.${OLD_VERSION}"
mv "${NEW_VERSION}-upgrade.md.new" "${NEW_VERSION}-upgrade.md"

backup_path="backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env -f "$COMPOSE_FILE" exec -T db \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' \
  > "${backup_path}"
test -s "${backup_path}"
docker compose --env-file .env -f "$COMPOSE_FILE" exec -T db \
  pg_restore --list < "${backup_path}" >/dev/null
printf 'backup=%s bytes=%s validated=1\n' "${backup_path}" "$(stat -c %s "${backup_path}")"
```

## Upgrade

```bash
set -euo pipefail
cd /srv/apps/prisma
export NEW_VERSION=v0.1.0-rc.35
export COMPOSE_FILE=compose.hospital.yml

umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${NEW_VERSION}/" .env > .env.new
grep -n "^SIRHOSP_VERSION=${NEW_VERSION}$" .env.new
chmod 600 .env.new
mv .env.new .env
mv "${COMPOSE_FILE}.new" "${COMPOSE_FILE}"

docker compose --env-file .env -f "$COMPOSE_FILE" config --quiet
docker compose --env-file .env -f "$COMPOSE_FILE" pull
docker compose --env-file .env -f "$COMPOSE_FILE" run --rm web \
  uv run --no-sync python manage.py migrate --noinput
docker compose --env-file .env -f "$COMPOSE_FILE" \
  up -d --remove-orphans --scale persistent_worker=10 \
  db web persistent_worker summary_worker

# Units da MESMA tag instalados sem habilitar nem iniciar nada.
sudo install -m 0644 deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/
systemctl daemon-reload
for timer in sirhosp-discharges.timer sirhosp-historical-recovery.timer sirhosp-daily-statistics.timer; do
  printf 'legacy_timer_state=%s enabled=%s active=%s\n' "${timer}" \
    "$(systemctl is-enabled "${timer}" || true)" \
    "$(systemctl is-active "${timer}" || true)"
done
```

O `migrate --noinput` aplica as migrations `0006` (`file_count`, backfill
`1`) e `0007` (só `help_text`). O `census_orchestrator` permanece parado
durante os primeiros smokes.

## Validação antes de retomar produtores

```bash
set -euo pipefail
cd /srv/apps/prisma
export COMPOSE_FILE=compose.hospital.yml

docker compose --env-file .env -f "$COMPOSE_FILE" ps
docker compose --env-file .env -f "$COMPOSE_FILE" exec -T web \
  uv run --no-sync python manage.py check

health_host="$(grep -E '^DJANGO_ALLOWED_HOSTS=' .env | cut -d= -f2- | cut -d, -f1)"
host_port="$(grep -E '^DJANGO_PORT=' .env | cut -d= -f2-)"
test -n "${health_host}"
test -n "${host_port}"

curl -fsS -H "Host: ${health_host}" \
  "http://127.0.0.1:${host_port}/health/"
for path in painel/ painel/altas/ altas/ reconciliacao/ statistics/; do
  code="$(
    curl -sS -o /dev/null -w '%{http_code}' -H "Host: ${health_host}" \
      "http://127.0.0.1:${host_port}/${path}"
  )"
  printf '%s http=%s\n' "${path}" "${code}"
  test "${code}" = "302"
done
```

Critérios de aceite antes da retomada:

- web saudável e `/health/` responde com sucesso;
- rotas autenticadas (incluindo `statistics/`) redirecionam usuário anônimo
  para login;
- 10 réplicas de `persistent_worker` ativas;
- web e workers na tag exata `v0.1.0-rc.35`;
- os três timers de fallback `disabled`/`inactive`;
- nenhum container em crash loop.

Conferência manual do operador (novidade da release): com usuário
autorizado, abrir `/statistics/` e baixar a exportação — o download deve ser
um `.zip` com um `.xlsx` por setor; o botão agora diz `Exportar ZIP por setor`.

## Rollback

Rollback code-only seguro: a coluna extra `file_count` é ignorada pelo
código da rc.34, então basta voltar imagem e Compose — sem restauração de
banco. Pare os produtores e drene novamente a fila antes de recriar os
workers se o sistema já tiver retomado o processamento.

```bash
set -euo pipefail
cd /srv/apps/prisma
export OLD_VERSION=v0.1.0-rc.34
export COMPOSE_FILE=compose.hospital.yml

systemctl stop sirhosp-stale-reconciliation.timer
docker compose --env-file .env -f "$COMPOSE_FILE" stop census_orchestrator

umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${OLD_VERSION}/" .env \
  > .env.rollback
chmod 600 .env.rollback
mv .env.rollback .env
cp "${COMPOSE_FILE}.${OLD_VERSION}" "$COMPOSE_FILE"

docker compose --env-file .env -f "$COMPOSE_FILE" config --quiet
docker compose --env-file .env -f "$COMPOSE_FILE" pull
docker compose --env-file .env -f "$COMPOSE_FILE" \
  up -d --remove-orphans --scale persistent_worker=10 \
  db web persistent_worker summary_worker
```

Valide a versão anterior antes de reativar o orquestrador e o timer. O backup
PostgreSQL é uma salvaguarda operacional e não deve ser restaurado neste
rollback code-only. Pare e investigue antes de qualquer restauração de banco.
