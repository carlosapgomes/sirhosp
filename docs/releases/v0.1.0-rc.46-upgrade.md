# Runbook de upgrade — v0.1.0-rc.46

Upgrade hospitalar da `v0.1.0-rc.45` para a `v0.1.0-rc.46` **com reparo de
dados autorizado** (identidade de setor dos censo DOM de 01/11).

## Escopo

- `c21bb0e` — corrigir o código de setor publicado pelo censo DOM: o CSV
  volta a publicar o **id interno da unidade** (input) como
  `setor_codigo` e o **label nativo completo** como `setor` (paridade
  XLSX/catálogo). Detalhes e evidências: `2026-11-01_v0.1.0-rc.46.md`.
- Sem migration (`migrate` é no-op; `census.0026` já aplicada pela rc.45).
- Reparo (autorizado pelo operador em 01/11): snapshots, movimentos e
  medições de ocupação das 4 execuções DOM de 01/11 (15:02, 16:42, 18:22,
  20:21 local).

## Impacto operacional

- A partir do primeiro ciclo pós-upgrade, `/beds` volta a exibir ocupação
  real (~89% na época do reparo) e a estatística diária de 02/11 (finaliza
  07:30) usa medições corrigidas.
- A estatística diária de 01/11 não é afetada (finalizada às 07:30 com
  medições XLSX saudáveis).
- Rollback: imagem rc.45 (funcional, exceto o bug de ocupação); não há
  migration para reverter.

## Pré-condições

1. Confirmar versão atual `v0.1.0-rc.45` e PostgreSQL saudável.
2. Parar produtores e drenar até `drain_state=0 0`.
3. Baixar assets da release imutável rc.46 (Compose `cd0e444c…`).
4. Backup PostgreSQL custom + `pg_restore --list`.

## Download e backup

```bash
set -euo pipefail
export OLD_VERSION=v0.1.0-rc.45
export NEW_VERSION=v0.1.0-rc.46
export COMPOSE_FILE=compose.hospital.yml
cd /srv/apps/prisma
curl -fL --retry 3 -o "${NEW_VERSION}-upgrade.md.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${NEW_VERSION}-upgrade.md"
curl -fL --retry 3 -o "${COMPOSE_FILE}.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${COMPOSE_FILE}"
for unit in sirhosp-discharges.service sirhosp-discharges.timer \
  sirhosp-historical-recovery.service sirhosp-historical-recovery.timer \
  sirhosp-stale-reconciliation.service sirhosp-stale-reconciliation.timer \
  sirhosp-daily-statistics.service sirhosp-daily-statistics.timer; do
  curl -fL --retry 3 -o "deploy/systemd/${unit}" \
    "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${unit}"
done
sha256sum "${COMPOSE_FILE}.new"   # cd0e444c…
cp -p "$COMPOSE_FILE" "${COMPOSE_FILE}.${OLD_VERSION}"
mv "${NEW_VERSION}-upgrade.md.new" "${NEW_VERSION}-upgrade.md"

backup_path="backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db sh -c \
  'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' > "${backup_path}"
test -s "${backup_path}"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db pg_restore --list < "${backup_path}" >/dev/null
echo "backup=${backup_path}"
```

## Reparo de dados (autorizado; execute com produtores ainda parados)

Um único script Python (via `manage.py shell -c` ou container web) faz:
mapear label→id a partir da run XLSX `2941190`; atualizar snapshots das
runs DOM de 01/11; consolidar movimentos de 01/11 (label completo vence,
mesclar duplicatas preservando `source_movement_at`); apagar e
re-materializar as medições 1148–1151; imprimir contadores agregados.
Rodar passo a passo abaixo e conferir cada saída.

### 1. Mapeamento e snapshots

```bash
docker compose --env-file .env -f compose.hospital.yml exec -T web \
  uv run --no-sync python manage.py shell -c '
from apps.census.models import CensusSnapshot
from django.utils import timezone as tz
today = tz.localtime().date()
src = CensusSnapshot.objects.filter(ingestion_run_id=2941190)
mapping = {}
for setor, codigo in src.values_list("setor", "setor_codigo").distinct():
    mapping[setor.strip()] = codigo.strip()
dom_ids = list(CensusSnapshot.objects.filter(
    ingestion_run__intent="census_extraction",
    captured_at__date=today,
).exclude(ingestion_run_id=2941190).values_list("ingestion_run_id").distinct())
fixed = unmatched = 0
for rid, in dom_ids:
    for snap in CensusSnapshot.objects.filter(ingestion_run_id=rid):
        label = f"{snap.setor_codigo} - {snap.setor}"
        code = mapping.get(label)
        if code is None:
            unmatched += 1
            continue
        if snap.setor != label or snap.setor_codigo != code:
            snap.setor, snap.setor_codigo = label, code
            snap.save(update_fields=("setor", "setor_codigo"))
            fixed += 1
print("runs", dom_ids, "fixed", fixed, "unmatched", unmatched)
'
```

Critério: `unmatched == 0`; `fixed` ≈ 4 × ~850.

### 2. Movimentos de 01/11 (consolidação)

  uv run --no-sync python manage.py shell -c '

    movement_date=today, sector__regex=r"^[^0-9]"

merged = kept = 0
for mv in short:

        patient=mv.patient, movement_date=today, sector__startswith="0 "

    # rótulo completo termina com a descrição curta
    match = [
        m for m in PatientMovement.objects.filter(
            patient=mv.patient, movement_date=today

        if m.sector.endswith(" - " + mv.sector)
    ]

        target = match[0]
        if target.source_movement_at is None and mv.source_movement_at:
            target.source_movement_at = mv.source_movement_at
            target.save(update_fields=("source_movement_at",))
