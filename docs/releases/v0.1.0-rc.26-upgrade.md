# Runbook de Upgrade — v0.1.0-rc.26 (2026-09-08)

## Escopo

Implementa o change `add-user-profile-and-self-service-password`
(autosserviço de conta — opção 2 da decisão do operador):

1. **`1015b98` (AUP-S1)**: página `/perfil/` para o usuário autenticado —
   identidade somente leitura (username, nome, e-mail, último login,
   papel: admin × usuário comum) e troca da própria senha
   (`PasswordChangeForm`: senha atual obrigatória, validadores do
   projeto, sessão preservada via `update_session_auth_hash`); link
   "Perfil" no rodapé do sidebar.
2. **`4a6ee39` (AUP-S2)**: `UserProfile` (flag `must_change_password`),
   middleware que força usuário com senha provisória a trocá-la em
   `/perfil/` antes de usar o resto do portal (allowlist: `/perfil/`,
   `/login/`, `/logout/`, `/admin/`, `/static/`, `/health/`,
   `/accounts/`), e o comando `create_portal_user` (cria usuário comum
   ativo com senha provisória aleatória impressa uma única vez como
   `temporary_password=<token>`; `--reset-password` reemite).

- Base do upgrade: **v0.1.0-rc.25** (`525bba9`).
- Suítes: unit **3586** / integration **676** (rc.25: 3586/656; +20
  casos novos de perfil/provisionamento), typecheck 416 arquivos.
- **Uma migration**: `accounts.0001_initial` (tabela `accounts_userprofile`
  **vazia** — nenhum usuário existente recebe perfil; usuários sem perfil
  não são afetados pelo middleware).

## Decisão do operador registrada (2026-09-08)

- A conta da diretora **não é tocada**: senha forte existente permanece,
  sem reset e sem troca forçada (ela só ganha a opção de trocar em
  `/perfil/`).
- O provisionamento das 5 enfermeiras será feito **manualmente pelo
  operador** (ver seção abaixo). O deploy não provisiona ninguém.

## Procedimento

1. Janela com fila **totalmente drenada** (`queued=0` **e** `running=0` —
   lição da rc.25: run órfão deixou o orquestrador blocked por 2h).
2. `sed -i "s/v0.1.0-rc.25/v0.1.0-rc.26/g" .env` e `pull`.
3. `docker compose --env-file .env -f compose.hospital.yml up -d`
   seguido de `--scale persistent_worker=10` (lição da rc.25: sem a
   flag o compose volta a 1 réplica).
4. **`migrate` obrigatório** (aplica `accounts.0001_initial`).
5. Validar: `ps` 13× rc.26, healthcheck web, log do orquestrador INFO
   normal.

## Provisionamento (manual, pelo operador)

Para cada enfermeira, no host de produção:

```bash
cd /srv/apps/prisma
docker compose --env-file .env -f compose.hospital.yml exec -T web \
  uv run --no-sync python manage.py create_portal_user <username> \
  --full-name "Nome Completo Da Enfermeira"
```

- Anote a linha `temporary_password=...` impressa (ela **não** é
  armazenada; aparece uma única vez) e entregue-a pessoalmente.
- A enfermeira entra em `/login/`, é redirecionada para `/perfil/` e só
  prossegue após definir a própria senha (validadores de força).
- Reemissão (esquecimento): o mesmo comando com
  `--reset-password <username>` reemite provisória e religa a troca
  forçada.
- A diretora: **nenhum comando** — conta e senha atuais intocadas.

## Rollback

- Imagem: `.env` de volta para `v0.1.0-rc.25` + `up -d` (a migration
  `accounts.0001_initial` é aditiva — tabela nova vazia; sem downgrade
  de dados necessário para rodar a rc.25).
- Remover perfis de teste se desejado: apagar linhas de
  `accounts_userprofile` (nenhum dado clínico envolvido).

## Validação pós-upgrade

- `docker compose ps` — todos `v0.1.0-rc.26` (13 serviços + db).
- Log do orquestrador: ciclos INFO normais (D-1/hourly inalterados).
- `/perfil/` acessível para qualquer usuário logado (sidebar → Perfil).
