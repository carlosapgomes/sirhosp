# SIRHOSP v0.1.0-rc.12 — Melhorias de UX da página `/beds` (somente UI)

## Status do artefato

Este é o runbook de pré-publicação da candidata `v0.1.0-rc.12`. Ele somente se
torna um asset operacional válido quando anexado, antes da publicação, à
release GitHub imutável da mesma tag e quando a imagem exata existir no GHCR.

O upgrade parte de `v0.1.0-rc.11` (já em produção desde 2026-08-25, com o
catálogo `occupancy-v5` vigente desde 2026-08-26). Esta etapa publica e
implanta **somente UI**: sem migration, sem catálogo e sem ativação — não há
migration nova, não há catálogo novo, não há comando de ativação nem de
ensaio de execução.
O `v5` já é vigente e as medições continuam
sendo criadas pelo fluxo natural. O `migrate` é executado apenas por
idempotência e deve resultar em `No migrations to apply`.

## Resumo da release

A RC12 entrega exclusivamente apresentação da página autenticada `/beds`
(change OpenSpec `improve-beds-v5-page-ux`, slices IBPU-S1/S2/S3):

- seção `Situação real do hospital` entre o resumo oficial e a lista de
  setores, derivada da reconciliação física persistida (somente branch v5);
- ponte v5 compacta ao fim da página, recolhida por padrão;
- métricas oficiais nos cabeçalhos dos cards v5 (capacidade, pacientes,
  saldo), derivadas das linhas oficiais persistidas, sem badges de contagem
  de códigos nem política por paciente;
- fim do N+1 no grafo catálogo→grupos→memberships com prefetch em ponto
  único: custo de queries da página constante, independente do catálogo.

A release não altera schema, catálogos, medições, resumos, filas,
autenticação, exact-run, gate de setores, políticas de capacidade, história
v1–v4 nem o fluxo clínico. Não há backfill, ativação, ensaio de execução,
migration nem mudança de dados.

## Backup obrigatório

Com somente o banco ativo:

```bash

chmod 700 /srv/apps/prisma/backups

  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' \
  > "${BACKUP_FILE}"
test -s "${BACKUP_FILE}"
sha256sum "${BACKUP_FILE}" > "${BACKUP_FILE}.sha256"
chmod 600 "${BACKUP_FILE}" "${BACKUP_FILE}.sha256"
sha256sum -c "${BACKUP_FILE}.sha256"
stat -c '%a %s %n' /srv/apps/prisma/backups \
  "${BACKUP_FILE}" "${BACKUP_FILE}.sha256"
```

O backup é obrigatório mesmo sem migration nova. Não copie o backup para o
repositório, release ou diretório público.

## Rollback trivial

A RC12 não muda schema nem dados: os dados v5 são imutáveis e independentes
da UI. O rollback é um redeploy da RC11 já preservada:

1. pare serviços mutantes na ordem segura (`census_orchestrator web`, drene,
   depois `persistent_worker summary_worker`);
2. restaure `compose.hospital.yml.rc11` sobre `compose.hospital.yml`;
3. selecione `SIRHOSP_VERSION=v0.1.0-rc.11` no `.env` sem imprimi-lo;
4. `config --quiet`, `pull` e retome a topologia com dez workers;
5. confirme health, revisão e catálogo v5 idêntico.

Não reverta migrations nem restaure backup apenas para rollback funcional;
o backup existe para incidentes que exijam restauração coordenada.
