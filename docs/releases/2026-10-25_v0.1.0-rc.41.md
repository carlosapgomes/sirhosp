## Mudanças comportamentais

1. Óbito com apenas data e **match único** por contenção de data local
   (`America/Bahia`) reconcilia como `death` em precisão de data:
   internação fechada em D 00:00 local (portadora), evento com marcador
   `death_exit={"precision":"date","local_date":D}`, `obito_em` nulo.
2. Ambíguo/não-resolvido permanece fail-closed com reasons explícitos
   (`deaths:ambiguous`, `deaths:patient_not_found`,
   `deaths:admission_not_found`); `deaths:date_only` é extinto.
3. Rollback de lote/operação restaura internação **e** evidência com o
   status pré-apply exato (fallback `pending` para eventos legados);
   desfechos `already_reconciled` são irreversíveis por design (bloqueio
   explícito, testado).
4. Portal e admin exibem apenas a data (com indicador de precisão) para
   fechamentos date-only; controles datetime completos mantêm a hora.
5. Agregações por data local insensíveis à hora portadora; óbitos seguem
   excluídos dos indicadores de altas.

## Notas honestas (pendências conscientes, não bloqueadoras)

- Tensão preexistente com "Every applied change is reversible": desfechos
  `already_reconciled` alteram status da evidência sem ser reversíveis
  (padrão análogo existe na coorte `discharges`) — registrada para
  decisão futura.
- Da massa de 777, apenas os itens com match único regularizam; o resto
  fica explicitamente classificado para revisão manual (fail-closed). A
  divisão exata só é conhecida no dry-run pós-deploy.
- Sem automação no runtime para óbitos novos: lotes ad hoc pelo comando
  (escopo deliberado da change).
