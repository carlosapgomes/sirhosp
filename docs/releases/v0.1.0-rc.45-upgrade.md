# Runbook de upgrade — v0.1.0-rc.45

Upgrade hospitalar da `v0.1.0-rc.44` para a `v0.1.0-rc.45`.

## Escopo

- `6cbb896` — hora real de movimentação na Trajetória (change OpenSpec
  `show-movement-time-in-trajectory`, SMT-S1/SMT-S2 aceitos):
  `PatientMovement.source_movement_at` opcional propagado pelo upsert
  (último snapshot com hora vence; null nunca apaga; sem backfill) e
  exibição `DD/MM/AAAA HH:MM` na coluna Entrada quando a hora existe
  (`DD/MM/AAAA` para entradas sem hora, na mesma trajetória). Durações
  permanecem date-based.

## Impacto operacional

- Release de código **com migration aditiva**
  `census.0026_patientmovement_source_movement_at` (coluna anulável em
  `PatientMovement`, sem backfill, sem índice): `migrate --noinput`
  **não é no-op** nesta release, mas é seguro e idempotente. Nenhuma outra
  migration deve aparecer.
- Assets de runtime byte a byte idênticos aos das rc.34–rc.44 (Compose
  `cd0e444c…`). Nenhuma variável de ambiente, serviço ou timer novo.
- Movimentos históricos permanecem sem hora; a partir do primeiro ciclo
  pós-upgrade, movimentos (re)observados passam a carregar a hora da fonte.
  A UI mostra a mistura data-only/data+hora por design.
- Rollback por imagem para a rc.44 (totalmente funcional): não desfaça a
  migration nem restaure o banco — a coluna opcional fica sem consumidor no
  código anterior.

## Pré-condições

1. Confirmar a versão atual (`v0.1.0-rc.44`) sem imprimir outras variáveis
   do `.env`.
2. Confirmar PostgreSQL saudável.
3. Parar produtores (`census_orchestrator`,
   `sirhosp-stale-reconciliation.timer`) e drenar até `drain_state=0 0`
   (checagem da seção 5c do `deploy/README.md`).
4. Baixar da release imutável o Compose, os units e este runbook.
5. Backup PostgreSQL custom + `pg_restore --list`.

## Download e backup

```bash
set -euo pipefail
export OLD_VERSION=v0.1.0-rc.44
export NEW_VERSION=v0.1.0-rc.45
export COMPOSE_FILE=compose.hospital.yml
cd /srv/apps/prisma
curl -fL --retry 3 -o "${NEW_VERSION}-upgrade.md.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${NEW_VERSION}-upgrade.md"
curl -fL --retry 3 -o "${COMPOSE_FILE}.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${COMPOSE_FILE}"
curl -fL --retry 3 -o deploy/exit-reconciliation-scheduler.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/exit-reconciliation-scheduler.sh"
curl -fL --retry 3 -o deploy/daily-statistics-activation-preflight.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/daily-statistics-activation-preflight.sh"
chmod +x deploy/exit-reconciliation-scheduler.sh deploy/daily-statistics-activation-preflight.sh
for unit in sirhosp-discharges.service sirhosp-discharges.timer \
  sirhosp-historical-recovery.service sirhosp-historical-recovery.timer \
  sirhosp-stale-reconciliation.service sirhosp-stale-reconciliation.timer \
  sirhosp-daily-statistics.service sirhosp-daily-statistics.timer; do
  curl -fL --retry 3 -o "deploy/systemd/${unit}" \
    "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${unit}"
done
sha256sum "${COMPOSE_FILE}.new"   # cd0e444c…
cp -p "$COMPOSE_FILE" "${COMPOSE_FILE}.${OLD_VERSION}"
mv "${NEW_VERSION}-upgrade.md.new" "${NEW_VERSION}-upgrade.md"

backup_path="backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db sh -c \
  'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' > "${backup_path}"
test -s "${backup_path}"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db pg_restore --list < "${backup_path}" >/dev/null
echo "backup=${backup_path}"
```

## Upgrade

> **Atenção (anomalia registrada na rc.43/rc.44):** `docker compose up -d`
> executado dentro de heredoc `bash` via PTY retorna 0 **sem recriar** os
> containers. Execute o passo `up -d` como comando direto na linha de
> comando e confirme as imagens de todos os serviços ao final.

```bash
umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${NEW_VERSION}/" .env > .env.new
grep -n "^SIRHOSP_VERSION=${NEW_VERSION}$" .env.new
chmod 600 .env.new && mv .env.new .env
mv ${COMPOSE_FILE}.new $COMPOSE_FILE
docker compose --env-file .env -f $COMPOSE_FILE config --quiet
docker compose --env-file .env -f $COMPOSE_FILE pull
docker compose --env-file .env -f $COMPOSE_FILE run --rm web \
  uv run --no-sync python manage.py migrate --noinput
```

Em seguida, **direto na linha de comando** (fora de heredoc):

```bash
docker compose --env-file .env -f compose.hospital.yml up -d --remove-orphans \
  --scale persistent_worker=10 db web persistent_worker summary_worker
install -m 0644 deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/
systemctl daemon-reload
docker compose --env-file .env -f compose.hospital.yml ps --format '{{.Name}} {{.Image}}' | sort
```

Critério: **todos** os serviços de aplicação na imagem `v0.1.0-rc.45`
(12 containers: web, summary_worker e 10 persistent_workers; o db permanece
a imagem do PostgreSQL). `migrate` deve aplicar exatamente
`census.0026_patientmovement_source_movement_at... OK`.

Critérios: ciclo `Cycle succeeded` (ou rejeição fail-closed com motivo);
`com_hora > 0` entre os movimentos novos; na página de admissão, entradas
recentes da Trajetória exibem hora e antigas seguem data-only.

## Rollback

Somente imagem: a rc.44 está totalmente funcional (censo DOM operacional).
Não desfaça `census.0026` nem restaure o banco; a coluna opcional permanece
sem consumidor no código anterior. Pare produtores, drene, troque
`SIRHOSP_VERSION=v0.1.0-rc.44` e recrie os containers (mesmos passos acima;
o `migrate` da rc.44 é no-op).
