# Runbook de upgrade — v0.1.0-rc.42

Upgrade hospitalar da `v0.1.0-rc.41` para a `v0.1.0-rc.42`.

## Escopo

- `eeca803` — ODR-S1: o modo D-1 do `run_exit_reconciliation_runtime`
  ganha, após a extração canônica, o passo de reconciliação de óbitos
  date-only da data recuperada: classificação somente-leitura por
  registro (`decide_discharge_match`); apenas desfecho `reconciled`
  (match único por data local) alcança o writer — fecha o episódio em
  D 00:00 `America/Bahia` (portadora) com marcador date-only e
  proveniência de runtime (`details_json.runtime.mode="d1"`); todos os
  outros desfechos apenas contam no resumo agregado (nenhuma escrita).
  Marker `mode=d1-deaths result=success source=adaptive-orchestrator`
  emitido somente quando o passo conclui.
- `413a38e` — reparo de gate: injeção type-safe de stdout em teste.
- Change OpenSpec: `orchestrate-date-only-death-recovery` (spec
  `production-exit-reconciliation-runtime` MODIFICADA no archive).

## Impacto operacional

- **Sem migrations** (o passo `migrate` é no-op nesta release).
- Sem novas dependências; `compose.hospital.yml` (`cd0e444c…`), Dockerfile
  e units idênticos às rc.34–rc.41.
- A ativação é o próprio deploy: a **primeira janela silenciosa
  (01:00–05:00 `America/Bahia`) após o upgrade** executa o passo pela
  primeira vez. Nenhuma operação manual de dados faz parte desta release.
- Nada muda nos valores de óbitos de `/painel/` e `/obitos`
  (`DailyDeathCount`) nem nos indicadores de altas (design D6).
- Falha total do passo não aborta o recovery D-1 nem o loop; marker de
  altas permanece independente.

## Pré-condições

1. Confirmar a versão atual (`v0.1.0-rc.41`) sem imprimir outras variáveis
   do `.env`.
2. Confirmar PostgreSQL saudável.
3. Registrar a escala atual de `persistent_worker`; o baseline hospitalar é
   de 10 réplicas.
4. Parar temporariamente os produtores de novos ciclos (`census_orchestrator`
   e `sirhosp-stale-reconciliation.timer`), mantendo os workers ativos para
   drenar a fila.
5. Aguardar `IngestionRun` sem itens `queued` ou `running` e nenhum batch de
   censo aberto (mesma checagem de drenagem da seção 5c do `deploy/README.md`).
6. Baixar da release imutável o Compose, os units e este runbook.
7. Criar backup PostgreSQL em formato custom, confirmar arquivo não vazio e
   validar o catálogo com `pg_restore --list`.
8. Confirmar que os três timers de fallback (`sirhosp-discharges.timer`,
   `sirhosp-historical-recovery.timer` e `sirhosp-daily-statistics.timer`)
   estão `disabled` e `inactive`.

## Pausa e drenagem

No host hospitalar, como `root`, em `/srv/apps/prisma`:

```bash
systemctl stop sirhosp-stale-reconciliation.timer
docker compose --env-file .env -f compose.hospital.yml stop census_orchestrator
```

Confirme a drenagem antes de recriar os workers:

```bash
drain_state="$(
  docker compose --env-file .env -f compose.hospital.yml exec -T web \
    uv run --no-sync python -c \
    'import os,django; os.environ.setdefault("DJANGO_SETTINGS_MODULE","config.settings"); django.setup(); from apps.ingestion.models import IngestionRun,CensusExecutionBatch; print(IngestionRun.objects.filter(status__in=("queued","running")).count(), CensusExecutionBatch.objects.filter(status="running").count())'
)"
printf 'drain_state=%s\n' "$drain_state"
test "$drain_state" = "0 0"
```

Se ainda houver itens ativos, aguarde com os 10 workers em execução. Não
prossiga com a drenagem pendente.

## Download e backup

```bash
set -euo pipefail
export OLD_VERSION=v0.1.0-rc.41
export NEW_VERSION=v0.1.0-rc.42
export COMPOSE_FILE=compose.hospital.yml
cd /srv/apps/prisma
mkdir -p backups deploy/systemd
chmod 700 backups
curl -fL --retry 3 -o "${NEW_VERSION}-upgrade.md.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${NEW_VERSION}-upgrade.md"
curl -fL --retry 3 -o "${COMPOSE_FILE}.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${COMPOSE_FILE}"
curl -fL --retry 3 -o deploy/exit-reconciliation-scheduler.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/exit-reconciliation-scheduler.sh"
curl -fL --retry 3 -o deploy/daily-statistics-activation-preflight.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/daily-statistics-activation-preflight.sh"
chmod +x deploy/exit-reconciliation-scheduler.sh deploy/daily-statistics-activation-preflight.sh
for unit in sirhosp-discharges.service sirhosp-discharges.timer \
  sirhosp-historical-recovery.service sirhosp-historical-recovery.timer \
  sirhosp-stale-reconciliation.service sirhosp-stale-reconciliation.timer \
  sirhosp-daily-statistics.service sirhosp-daily-statistics.timer; do
  curl -fL --retry 3 -o "deploy/systemd/${unit}" \
    "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${unit}"
done
sha256sum "${COMPOSE_FILE}.new"
cp -p "$COMPOSE_FILE" "${COMPOSE_FILE}.${OLD_VERSION}"
mv "${NEW_VERSION}-upgrade.md.new" "${NEW_VERSION}-upgrade.md"

backup_path="backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db sh -c \
  'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' > "${backup_path}"
test -s "${backup_path}"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db pg_restore --list < "${backup_path}" >/dev/null
echo "backup=${backup_path}"
```

O hash do Compose deve ser `cd0e444c…` (idêntico à rc.34–rc.41).

## Upgrade

```bash
umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${NEW_VERSION}/" .env > .env.new
grep -n "^SIRHOSP_VERSION=${NEW_VERSION}$" .env.new
chmod 600 .env.new && mv .env.new .env
mv ${COMPOSE_FILE}.new $COMPOSE_FILE
docker compose --env-file .env -f $COMPOSE_FILE config --quiet

docker compose --env-file .env -f $COMPOSE_FILE pull
docker compose --env-file .env -f $COMPOSE_FILE run --rm web \
  uv run --no-sync python manage.py migrate --noinput
docker compose --env-file .env -f $COMPOSE_FILE up -d --remove-orphans \
  --scale persistent_worker=10 db web persistent_worker summary_worker

install -m 0644 deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/
systemctl daemon-reload
```

Esta release **não tem migrations**: o `migrate` deve reportar
`No migrations to apply.`. Qualquer migração inesperada aqui é critério
de parada.

todas as rotas autenticadas respondendo `302`.

## Rollback

- **Imagem**: recriar os containers com `SIRHOSP_VERSION=v0.1.0-rc.41`.
  Sem migrations nesta release, não há schema a reverter; não restaurar o
  banco apenas para voltar a versão.
- Fechamentos por morte eventualmente criados pelo passo noturno são
  eventos auditáveis reversíveis por operação
  (`rollback_admission_reconciliation --operation <uuid>`), sem restaurar
  banco — embora não haja cenário esperado que exija isso.
- Nunca desfazer migrations nem restaurar o banco como parte do rollback
  desta release.
