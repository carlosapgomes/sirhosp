# SIRHOSP v0.1.0-rc.10 — Qualidade de ocupação acionável

## Status do artefato

Este é o runbook de pré-publicação da candidata `v0.1.0-rc.10`. Ele somente se
torna um asset operacional válido quando anexado, antes da publicação, à
release GitHub imutável da mesma tag e quando a imagem exata existir no GHCR.

O upgrade parte de `v0.1.0-rc.9`. Esta etapa publica e implanta o código e aplica
as migrations aditivas 0022 e 0023. Ela não executa dry-run, não publica catálogo
v4 e não ativa `occupancy-v4`. O catálogo v3 deve permanecer vigente após o
deploy; dry-run e ativação continuam operações posteriores e separadas.

## Resumo da release

A RC10 entrega, ainda dormente até catálogo futuro explícito:

- `occupancy-v4` com duplicatas consolidadas antes da tipagem;
- conflitos de ocupante, status e faixa etária tratados por impacto;
- reconciliação agregada schema 2, fechada e sem dados identificáveis;
- medições v4 elegíveis para resumo diário com contador próprio de ressalvas;
- aliases limpos, curados e temporais por código-fonte;
- dois resumos agregados e uma única lista `Setores e posições` em `/beds`;
- terminologia `sistema de origem`;
- detalhes não autoritativos para todos os usuários autenticados;
- ADR-0006 substituindo parcialmente decisões de conflito e apresentação da
  ADR-0005.

A release não altera o gate de 40 setores, capacidade 666, política do Centro
Obstétrico, partição 32/16 da 3A, exact-run, autenticação ou fluxo clínico. Não
faz backfill nem reinterpreta v1–v3.

## Regras de segurança

e o banco PostgreSQL da aplicação. Não altere host, rede `hospital_edge`,
Cloudflared, systemd ou outras aplicações.

## Backup obrigatório

Com somente o banco ativo:

```bash
mkdir -p /srv/apps/prisma/backups
chmod 700 /srv/apps/prisma/backups
export BACKUP_FILE="/srv/apps/prisma/backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env -f compose.hospital.yml exec -T db \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' \
  > "${BACKUP_FILE}"
test -s "${BACKUP_FILE}"
sha256sum "${BACKUP_FILE}" > "${BACKUP_FILE}.sha256"
chmod 600 "${BACKUP_FILE}" "${BACKUP_FILE}.sha256"
sha256sum -c "${BACKUP_FILE}.sha256"
stat -c '%a %s %n' /srv/apps/prisma/backups \
  "${BACKUP_FILE}" "${BACKUP_FILE}.sha256"
```

Não copie o backup para o repositório, release ou diretório público.

## Rollback antes da ativação v4

As migrations 0022/0023 podem permanecer porque são aditivas. Para rollback
funcional antes da ativação v4:

1. pare serviços mutantes;
2. restaure `compose.hospital.yml.rc9`;
3. selecione `SIRHOSP_VERSION=v0.1.0-rc.9` sem imprimir `.env`;
4. faça pull e retome a topologia com dez workers;
5. confirme health, revisão e catálogo v3.

Não reverta migrations nem restaure backup apenas para rollback funcional. Após
vigência v4, não volte para versão sem suporte; prefira correção forward.
