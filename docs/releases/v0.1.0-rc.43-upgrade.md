# Runbook de upgrade — v0.1.0-rc.43

Upgrade hospitalar da `v0.1.0-rc.42` para a `v0.1.0-rc.43`.

## Escopo

- `838cbba` — troca da aquisição operacional do censo para leitura direta
  do DOM (change OpenSpec `extract-daily-census-from-dom`, slices ECD-S1 a
  ECD-S3): 11 campos + metadados de setor com paridade ao parser XLSX;
  seleção de setor nativa confirmada por código + descrição normalizada;
  tooltips de `Dt Int`/`Dt Mvt` associados à própria célula com espera
  limitada de 10 s; página longa nativa (100 ou menor ≥ 100) com travessia
  completa até o controle de próxima desabilitado (teto 50 páginas), sem
  truncamento/deduplicação; **sem exportação XLSX e sem fallback**.
- `CensusSnapshot` ganha `source_admission_at`/`source_movement_at`
  opcionais (aware, `America/Bahia`); projeções date-only e todos os
  consumidores existentes inalterados (sem horas na Trajetória, sem
  backfill).
- Publicação fail-closed do censo: resumo agregado v1 + CSV canônico
  consistentes são exigidos pelo `extract_census` antes de qualquer
  persistência; aceitação atômica por run; rejeição preserva o último censo
  aceito sem efeitos downstream.
- O intervalo também inclui chores documentais/spec da rc.42
  (`55c5b9e`, `738f21d`, `eeb16c0`, `3a3293c`), sem efeito de runtime.

## Impacto operacional

- Release de código **com migration aditiva**:
  `census.0025_censussnapshot_source_timestamps` apenas cria as duas colunas
  opcionais de origem. Nenhuma tabela existente é alterada e nenhum dado
  existente é modificado — `migrate --noinput` **não é no-op** nesta release,
  mas é seguro e idempotente, e não há backfill: snapshots existentes
  permanecem válidos com os campos nulos.
- Assets de runtime byte a byte idênticos aos das rc.34–rc.42 (Compose
  `cd0e444c…`, Dockerfile, units, scheduler e preflight). Nenhuma variável de
  ambiente, permissão, serviço ou timer novo.
- A ativação é o próprio deploy: o **primeiro ciclo de censo após o upgrade
  coleta por DOM** automaticamente. Nenhuma operação manual de dados faz
  parte desta release.
- O nome-base do CSV publicado passa a `censo-todos-pacientes-<ts>.csv`
  (antes `censo-todos-pacientes-xlsx-<ts>.csv`). O `extract_census` continua
  selecionando via glob `censo-*.csv` e nenhum código/script/timer referencia
  o literal antigo; **consumidores manuais** do literal antigo devem atualizar
  nesta janela.
- Coletor e command fazem parte da mesma imagem (contrato conjunto). Não
  compartilhe diretório de handoff entre versões e não publique CSV/resumo de
  uma versão para o command de outra.
- O rollback é somente de imagem: a rc.42 retoma a exportação XLSX; **não
  desfaça a migration nem restaure o banco** — as colunas opcionais podem
  permanecer e ficam sem consumidor no código antigo (ver seção Rollback).

## Pré-condições

1. Confirmar a versão atual (`v0.1.0-rc.42`) sem imprimir outras variáveis
   do `.env`.
2. Confirmar PostgreSQL saudável.
3. Registrar a escala atual de `persistent_worker`; o baseline hospitalar é
   de 10 réplicas.
4. Parar temporariamente os produtores de novos ciclos (`census_orchestrator`
   e `sirhosp-stale-reconciliation.timer`), mantendo os workers ativos para
   drenar a fila.
5. Aguardar `IngestionRun` sem itens `queued` ou `running` e nenhum batch de
   censo aberto (mesma checagem de drenagem da seção 5c do `deploy/README.md`).
6. Baixar da release imutável o Compose, os units e este runbook.
7. Criar backup PostgreSQL em formato custom, confirmar arquivo não vazio e
   validar o catálogo com `pg_restore --list`.
8. Confirmar que os três timers de fallback (`sirhosp-discharges.timer`,
   `sirhosp-historical-recovery.timer` e `sirhosp-daily-statistics.timer`)
   estão `disabled` e `inactive`.
9. Combinar com a equipe a janela de observação assistida do primeiro ciclo
   DOM (conferência somente leitura e agregada; sem pacientes de teste).

## Pausa e drenagem

No host hospitalar, como `root`, em `/srv/apps/prisma`:

```bash
systemctl stop sirhosp-stale-reconciliation.timer
docker compose --env-file .env -f compose.hospital.yml stop census_orchestrator
```

Confirme a drenagem antes de recriar os workers:

```bash
drain_state="$(
  docker compose --env-file .env -f compose.hospital.yml exec -T web \
    uv run --no-sync python -c \
    'import os,django; os.environ.setdefault("DJANGO_SETTINGS_MODULE","config.settings"); django.setup(); from apps.ingestion.models import IngestionRun,CensusExecutionBatch; print(IngestionRun.objects.filter(status__in=("queued","running")).count(), CensusExecutionBatch.objects.filter(status="running").count())'
)"
printf 'drain_state=%s\n' "$drain_state"
test "$drain_state" = "0 0"
```

Se ainda houver itens ativos, aguarde com os 10 workers em execução. Não
prossiga com a drenagem pendente.

## Download e backup

```bash
set -euo pipefail
export OLD_VERSION=v0.1.0-rc.42
export NEW_VERSION=v0.1.0-rc.43
export COMPOSE_FILE=compose.hospital.yml
cd /srv/apps/prisma
mkdir -p backups deploy/systemd
chmod 700 backups
curl -fL --retry 3 -o "${NEW_VERSION}-upgrade.md.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${NEW_VERSION}-upgrade.md"
curl -fL --retry 3 -o "${COMPOSE_FILE}.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${COMPOSE_FILE}"
curl -fL --retry 3 -o deploy/exit-reconciliation-scheduler.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/exit-reconciliation-scheduler.sh"
curl -fL --retry 3 -o deploy/daily-statistics-activation-preflight.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/daily-statistics-activation-preflight.sh"
chmod +x deploy/exit-reconciliation-scheduler.sh deploy/daily-statistics-activation-preflight.sh
for unit in sirhosp-discharges.service sirhosp-discharges.timer \
  sirhosp-historical-recovery.service sirhosp-historical-recovery.timer \
  sirhosp-stale-reconciliation.service sirhosp-stale-reconciliation.timer \
  sirhosp-daily-statistics.service sirhosp-daily-statistics.timer; do
  curl -fL --retry 3 -o "deploy/systemd/${unit}" \
    "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${unit}"
done
sha256sum "${COMPOSE_FILE}.new"
cp -p "$COMPOSE_FILE" "${COMPOSE_FILE}.${OLD_VERSION}"
mv "${NEW_VERSION}-upgrade.md.new" "${NEW_VERSION}-upgrade.md"

backup_path="backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db sh -c \
  'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' > "${backup_path}"
test -s "${backup_path}"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db pg_restore --list < "${backup_path}" >/dev/null
echo "backup=${backup_path}"
```

O hash do Compose deve ser `cd0e444c…` (idêntico à rc.34–rc.42).

## Upgrade

```bash
umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${NEW_VERSION}/" .env > .env.new
grep -n "^SIRHOSP_VERSION=${NEW_VERSION}$" .env.new
chmod 600 .env.new && mv .env.new .env
mv ${COMPOSE_FILE}.new $COMPOSE_FILE
docker compose --env-file .env -f $COMPOSE_FILE config --quiet

docker compose --env-file .env -f $COMPOSE_FILE pull
docker compose --env-file .env -f $COMPOSE_FILE run --rm web \
  uv run --no-sync python manage.py migrate --noinput
docker compose --env-file .env -f $COMPOSE_FILE up -d --remove-orphans \
  --scale persistent_worker=10 db web persistent_worker summary_worker

install -m 0644 deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/
systemctl daemon-reload
```

`migrate --noinput` aplica `census.0025_censussnapshot_source_timestamps`
(aditiva: duas colunas opcionais, sem backfill). Nenhuma outra migration deve
aparecer — migration inesperada é critério de parada. O
`census_orchestrator` permanece parado durante os primeiros smokes.

docker compose --env-file .env -f $COMPOSE_FILE ps

health_host="$(grep -E "^DJANGO_ALLOWED_HOSTS=" .env | cut -d= -f2- | cut -d, -f1)"

## Observação do primeiro ciclo de censo DOM (assistida, somente leitura)

Após retomar os produtores, observe o primeiro ciclo de censo da versão nova.
A conferência é de leitura e usa apenas linhas agregadas e contagens — não
crie pacientes de teste em produção.

Blocos agregados da coleta nos logs (contagens e caminhos, sem identidade):

```bash
docker compose --env-file .env -f $COMPOSE_FILE logs --since 24h \
  census_orchestrator persistent_worker | \
  grep -E "Setores encontrados|Setores com erro|Total pacientes|CSV:|Resumo:" | tail -20
```

Contagens de snapshots do último run no PostgreSQL (agregadas):

```bash
docker compose --env-file .env -f $COMPOSE_FILE exec -T web \
  uv run --no-sync python -c \
  'import os,django; os.environ.setdefault("DJANGO_SETTINGS_MODULE","config.settings"); django.setup(); from apps.census.models import CensusSnapshot; latest=CensusSnapshot.objects.order_by("-extracted_at").first(); qs=CensusSnapshot.objects.filter(ingestion_run=latest.ingestion_run) if latest else CensusSnapshot.objects.none(); print("run=", latest.ingestion_run_id if latest else None, "snapshots=", qs.count(), "com_source_admission=", qs.filter(source_admission_at__isnull=False).count(), "com_source_movement=", qs.filter(source_movement_at__isnull=False).count())'
```

Critérios:

- ciclo concluído com resumo `scope_complete=true` e CSV publicado, **ou**
  rejeição fail-closed com motivo agregado (0 CSV parcial é o comportamento
  correto de rejeição, não uma falha do gate);
- se o censo aceito tiver datas preenchidas na fonte, `com_source_admission`
  e/ou `com_source_movement` devem ser > 0; leitos/rótulos sem registro
  permanecem nulos por design;
- rejeições com motivos `page_size_unsupported`, `pagination_state_unknown`
  ou `tooltip_not_ready` indicam formato real do paginador/tooltip diferente
  do sintético — registrar e escalar (a coleta falha fechada; nada é
  publicado parcial).

## Rollback

O rollback é somente de imagem; **não desfaça a migration
`census.0025_...` e não restaure o banco**: as colunas são aditivas e
opcionais, e a imagem rc.42 as ignora sem impacto. Não apague snapshots. Pare
os produtores e drene novamente a fila antes de recriar os workers se o
sistema já tiver retomado o processamento.

```bash
set -euo pipefail
cd /srv/apps/prisma
export OLD_VERSION=v0.1.0-rc.42
export COMPOSE_FILE=compose.hospital.yml

systemctl stop sirhosp-stale-reconciliation.timer
docker compose --env-file .env -f $COMPOSE_FILE stop census_orchestrator

umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${OLD_VERSION}/" .env \
  > .env.rollback
chmod 600 .env.rollback
grep -n "^SIRHOSP_VERSION=${OLD_VERSION}$" .env.rollback
mv .env.rollback .env
cp -p "${COMPOSE_FILE}.${OLD_VERSION}" "$COMPOSE_FILE"
docker compose --env-file .env -f $COMPOSE_FILE config --quiet
docker compose --env-file .env -f $COMPOSE_FILE pull
docker compose --env-file .env -f $COMPOSE_FILE up -d --remove-orphans \
  --scale persistent_worker=10 db web persistent_worker summary_worker
```

A rc.42 volta a coletar via exportação XLSX. O último censo aceito pela
rc.43 permanece válido (campos de origem ficam sem consumidor no código
antigo). Snapshots criados pela rc.43 não são alterados pelo rollback. Após
a investigação, um novo upgrade segue este runbook do início.
