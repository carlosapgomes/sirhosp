# SIRHOSP v0.1.0-rc.11 — Ocupação v5 dormente por pacientes identificados

## Status do artefato

Este é o runbook de pré-publicação da candidata `v0.1.0-rc.11`. Ele somente se
torna um asset operacional válido quando anexado, antes da publicação, à
release GitHub imutável da mesma tag e quando a imagem exata existir no GHCR.

O upgrade parte de `v0.1.0-rc.10`. Esta etapa publica e implanta o código e aplica
a migration aditiva 0024. Ela não executa dry-run, não publica catálogo v5 e não
ativa `occupancy-v5`. O catálogo v4 deve permanecer vigente após o deploy;
dry-run e publicação v5 continuam operações posteriores e separadas (slices
CIPOO-S5/S6).

## Resumo da release

A RC11 entrega, ainda dormente até catálogo futuro explícito:

- `occupancy-v5` contando pacientes identificados por prontuário numérico e
  nome válido, deduplicados por grupo oficial, sem usar identidade de leito;
- paciente sem leito contado, pacientes distintos no mesmo leito contados
  separadamente e partição 3A com fallback determinístico `RN`;
- reconciliação agregada schema 3, fechada e sem dados identificáveis;
- medições v5 elegíveis para resumo diário com contador próprio de ressalvas;
- catálogo integral futuro `sector_capacity_catalog_v5.json` preservando
  43/48/47, 39 standard, quatro unrated, 666/666, aliases 48/48, CO e 3A;
- `/beds` v5 com um único card de capacidade, `Pacientes identificados`,
  `Saldo da capacidade oficial` e lista `Setores, pacientes e estados de
  leitos` com mensagens factuais sem linguagem de conflito;
- ADR-0007 substituindo parcialmente as ADR-0005/0006 somente para v5.

A release não altera o gate de 40 setores, capacidade 666, política do Centro
Obstétrico, partição 32/16 da 3A, exact-run, autenticação ou fluxo clínico. Não
faz backfill nem reinterpreta v1–v4.

## Backup obrigatório

```bash

chmod 700 /srv/apps/prisma/backups

docker compose --env-file .env -f compose.hospital.yml exec -T db \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' \
  > "${BACKUP_FILE}"
test -s "${BACKUP_FILE}"
sha256sum "${BACKUP_FILE}" > "${BACKUP_FILE}.sha256"
chmod 600 "${BACKUP_FILE}" "${BACKUP_FILE}.sha256"
sha256sum -c "${BACKUP_FILE}.sha256"
stat -c '%a %s %n' /srv/apps/prisma/backups \
  "${BACKUP_FILE}" "${BACKUP_FILE}.sha256"
```

Não copie o backup para o repositório, release ou diretório público.

## Rollback antes da ativação v5

As migrations 0024 podem permanecer porque são aditivas. Para rollback
funcional antes da ativação v5:

1. pare serviços mutantes;
2. restaure `compose.hospital.yml.rc10`;
3. selecione `SIRHOSP_VERSION=v0.1.0-rc.10` sem imprimir `.env`;
4. faça pull e retome a topologia com dez workers;
5. confirme health, revisão e catálogo v4.

Não reverta migrations nem restaure backup apenas para rollback funcional. Após
vigência v5, não volte para versão sem suporte; prefira correção forward.
