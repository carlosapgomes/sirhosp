# Runbook de upgrade — v0.1.0-rc.44

Upgrade hospitalar da `v0.1.0-rc.43` para a `v0.1.0-rc.44`.

## Escopo

- `0e4562e` — correção dirigida da aquisição DOM da rc.43 após o primeiro
  ciclo real falhar fail-closed (`discovery_incomplete`): descoberta de
  setores concluída apenas pelo fundo explícito do painel (o portal não é
  lazy); confirmação de seleção pela identidade nativa do label (o input
  guarda o id interno); extração do timestamp de tooltips com texto
  adicional (setores de observação); campos `setor_codigo`/`setor` do CSV
  com código e descrição nativos do setor confirmado.
- Fixture sintética e verificador obrigatório alinhados ao formato real
  evidenciado; sem mudanças de contrato de artefatos, persistência,
  bootstrap/proxy/CLI, serviços ou timers.

## Impacto operacional

- **Sem migrations**: o passo `migrate` deve reportar
  `No migrations to apply.` (`census.0025` já foi aplicada na rc.43).
- Assets de runtime byte a byte idênticos aos das rc.34–rc.43 (Compose
  `cd0e444c…`). Nenhuma variável de ambiente, serviço ou timer novo.
- A ativação é o deploy: o **primeiro ciclo automático de censo após a
  retomada do orquestrador** usa a coleta DOM corrigida. Durante a janela
  de upgrade o orquestrador permanece parado (como na rc.43).
- Estado na rc.43 que este upgrade resolve: coleta de censo bloqueada por
  rejeição fail-closed desde o upgrade anterior; o último censo aceito e
  todo o histórico permanecem intactos.

## Pré-condições

1. Confirmar a versão atual (`v0.1.0-rc.43`) sem imprimir outras variáveis
   do `.env`.
2. Confirmar PostgreSQL saudável.
3. `census_orchestrator` parado e fila drenada (`drain_state=0 0`), como
   deixado pela janela de diagnóstico da rc.43; se algo retomou, repetir a
   pausa e a drenagem do runbook rc.43.
4. Baixar da release imutável o Compose, os units e este runbook.
5. Backup PostgreSQL em formato custom + `pg_restore --list`.

## Download e backup

```bash
set -euo pipefail
export OLD_VERSION=v0.1.0-rc.43
export NEW_VERSION=v0.1.0-rc.44
export COMPOSE_FILE=compose.hospital.yml
cd /srv/apps/prisma
curl -fL --retry 3 -o "${NEW_VERSION}-upgrade.md.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${NEW_VERSION}-upgrade.md"
curl -fL --retry 3 -o "${COMPOSE_FILE}.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${COMPOSE_FILE}"
curl -fL --retry 3 -o deploy/exit-reconciliation-scheduler.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/exit-reconciliation-scheduler.sh"
curl -fL --retry 3 -o deploy/daily-statistics-activation-preflight.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/daily-statistics-activation-preflight.sh"
chmod +x deploy/exit-reconciliation-scheduler.sh deploy/daily-statistics-activation-preflight.sh
for unit in sirhosp-discharges.service sirhosp-discharges.timer \
  sirhosp-historical-recovery.service sirhosp-historical-recovery.timer \
  sirhosp-stale-reconciliation.service sirhosp-stale-reconciliation.timer \
  sirhosp-daily-statistics.service sirhosp-daily-statistics.timer; do
  curl -fL --retry 3 -o "deploy/systemd/${unit}" \
    "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${unit}"
done
sha256sum "${COMPOSE_FILE}.new"   # deve ser cd0e444c…
cp -p "$COMPOSE_FILE" "${COMPOSE_FILE}.${OLD_VERSION}"
mv "${NEW_VERSION}-upgrade.md.new" "${NEW_VERSION}-upgrade.md"

backup_path="backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db sh -c \
  'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' > "${backup_path}"
test -s "${backup_path}"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db pg_restore --list < "${backup_path}" >/dev/null
echo "backup=${backup_path}"
```

## Upgrade

```bash
umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${NEW_VERSION}/" .env > .env.new
grep -n "^SIRHOSP_VERSION=${NEW_VERSION}$" .env.new
chmod 600 .env.new && mv .env.new .env
mv ${COMPOSE_FILE}.new $COMPOSE_FILE
docker compose --env-file .env -f $COMPOSE_FILE config --quiet

docker compose --env-file .env -f $COMPOSE_FILE pull
docker compose --env-file .env -f $COMPOSE_FILE run --rm web \
  uv run --no-sync python manage.py migrate --noinput   # No migrations to apply.
docker compose --env-file .env -f $COMPOSE_FILE up -d --remove-orphans \
  --scale persistent_worker=10 db web persistent_worker summary_worker

install -m 0644 deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/
systemctl daemon-reload
```

Qualquer migration inesperada aqui é critério de parada.

## Rollback

O rollback é somente de imagem; não desfaça migrations e não restaure o
banco. A rc.43 retorna à coleta XLSX? **Não** — a rc.43 também coleta por
DOM (com o bug de descoberta); o rollback efetivo da coleta é a rc.42
(XLSX). Preferir corrigir para frente; se o rollback for inevitável:

```bash
systemctl stop sirhosp-stale-reconciliation.timer
docker compose --env-file .env -f compose.hospital.yml stop census_orchestrator
# drenar a fila antes de recriar os workers (runbook rc.43)
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=v0.1.0-rc.42/" .env > .env.rollback
chmod 600 .env.rollback && mv .env.rollback .env
cp -p compose.hospital.yml.v0.1.0-rc.42 compose.hospital.yml
docker compose --env-file .env -f compose.hospital.yml pull
docker compose --env-file .env -f compose.hospital.yml up -d --remove-orphans \
  --scale persistent_worker=10 db web persistent_worker summary_worker
```

As colunas opcionais da `census.0025` permanecem sem consumidor no código
antigo; snapshots existentes não são alterados.
