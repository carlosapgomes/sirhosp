# Runbook de upgrade — v0.1.0-rc.49

Upgrade hospitalar da `v0.1.0-rc.48` para a `v0.1.0-rc.49` (API de leitura
upstream `/api/v1/` para o consumidor interno hgproxy).

## Escopo

- `84a8ed2`–`c3a59f8` — change OpenSpec `sirhosp-upstream-api-v1` (UPA-001 a
  UPA-004 aceitos): app isolado `apps.upstream_api` com dois endpoints GET
  read-only — `GET /api/v1/inpatients/current` (foto do último ciclo de
  censo **concluído**, com `cycle_seq` monotônico v1.1) e
  `GET /api/v1/patients/{prontuario}` (demografia). Autenticação
  `Authorization: Bearer` estática; erros padronizados; timestamps ISO 8601;
  `Cache-Control: no-store`. Contrato de consumo:
  `docs/upstream-api.md`; evidência R1 (foto inteira ou nada):
  `docs/upstream-api-r1-evidence.md`.
- `3593b86` — guia do consumidor (docs).
- `9f2398e`, `f380062` — archive/sync OpenSpec e evidência R1; sem runtime.
- **Runtime novo**: `compose.hospital.yml` passa
  `SIRHOSP_UPSTREAM_API_TOKEN` ao ambiente compartilhado (asset muda de
  hash); `config/gunicorn.conf.py` usa `SanitizedAccessLogger` para
  `/api/v1/*` (método, rota sanitizada e status — nunca nome/prontuário);
  `LOGGING` filtra `django.request` para o mesmo fim; `/api/v1/` fora do
  redirect de troca forçada de senha (responde 401 próprio).
- Sem migrations (`migrate` é no-op; nenhuma app além das já existentes).

## Impacto operacional

- **Asset Compose muda de hash**: `cd0e444c…` → **`ee593a51…`**
  (`sha256sum compose.hospital.yml`). A única mudança funcional é a nova
  variável no ambiente compartilhado.
- **Nova variável de ambiente (decisão do operador)**:
  `SIRHOSP_UPSTREAM_API_TOKEN` — token Bearer estático, **mínimo 32 bytes
  aleatórios**.
  - **Vazia/ausente (padrão fail-closed, design D5)**: toda chamada
    `/api/v1/*` responde `500 internal_error`. A API fica inerte; o portal e
    todos os pipelines seguem 100% inalterados. O deploy pode subir assim.
  - **Configurada**: sem/invalid `Authorization` responde `401`; com token
    válido, os endpoints servem a foto e a demografia.
  - Para habilitar depois do upgrade, basta acrescentar a variável ao
    `.env` e recriar o `web` (e workers/orchestrator, que compartilham o
    ambiente): mesmo `up -d` deste runbook.
- O consumidor (hgproxy) ainda precisa de token, rede e proxy próprios
  antes do go-live (a evidência R1 não é autorização de go-live por si só);
  subir a API fail-closed não expõe nada.
- Logs de acesso a `/api/v1/*` são sanitizados por design (D6/R8/R10): nenhuma
  linha de log carrega nome ou prontuário, nem no gunicorn nem no
  `django.request`.
- Rollback por imagem para a rc.48 (totalmente funcional): se o token foi
  configurado, pode ficar no `.env` (a rc.48 não lê a variável); o
  `SanitizedAccessLogger` some com a imagem rc.48 e não há migration para
  reverter.

## Pré-condições

1. Confirmar versão atual `v0.1.0-rc.48` e PostgreSQL saudável.
2. Decidir o token: subir **fail-closed** (nada a fazer) ou gerar agora
   (`openssl rand -base64 32` no servidor; guardar com permissão restrita;
   o consumidor recebe por canal seguro, nunca por este runbook).
3. Parar produtores e drenar até `drain_state=0 0`:

   ```bash
   systemctl stop sirhosp-stale-reconciliation.timer
   docker compose --env-file .env -f compose.hospital.yml stop census_orchestrator
   drain_state="$(
     docker compose --env-file .env -f compose.hospital.yml exec -T web \
       uv run --no-sync python -c \
       'import os,django; os.environ.setdefault("DJANGO_SETTINGS_MODULE","config.settings"); django.setup(); from apps.ingestion.models import IngestionRun,CensusExecutionBatch; print(IngestionRun.objects.filter(status__in=("queued","running")).count(), CensusExecutionBatch.objects.filter(status="running").count())'
   )"
   printf 'drain_state=%s\n' "$drain_state"
   test "$drain_state" = "0 0"
   ```

4. Baixar assets da release imutável rc.49 (**Compose `ee593a51…`**).
5. Backup PostgreSQL custom + `pg_restore --list`.

## Download e backup

```bash
set -euo pipefail
export OLD_VERSION=v0.1.0-rc.48
export NEW_VERSION=v0.1.0-rc.49
export COMPOSE_FILE=compose.hospital.yml
cd /srv/apps/prisma
curl -fL --retry 3 -o "${NEW_VERSION}-upgrade.md.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${NEW_VERSION}-upgrade.md"
curl -fL --retry 3 -o "${COMPOSE_FILE}.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${COMPOSE_FILE}"
for unit in sirhosp-discharges.service sirhosp-discharges.timer \
  sirhosp-historical-recovery.service sirhosp-historical-recovery.timer \
  sirhosp-stale-reconciliation.service sirhosp-stale-reconciliation.timer \
  sirhosp-daily-statistics.service sirhosp-daily-statistics.timer; do
  curl -fL --retry 3 -o "deploy/systemd/${unit}" \
    "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${unit}"
done
sha256sum "${COMPOSE_FILE}.new"   # ee593a51…
cp -p "$COMPOSE_FILE" "${COMPOSE_FILE}.${OLD_VERSION}"
mv "${NEW_VERSION}-upgrade.md.new" "${NEW_VERSION}-upgrade.md"

backup_path="backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db sh -c \
  'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' > "${backup_path}"
test -s "${backup_path}"
docker compose --env-file .env -f $COMPOSE_FILE exec -T db pg_restore --list < "${backup_path}" >/dev/null
echo "backup=${backup_path}"
```

## Upgrade

> `docker compose up -d` **sempre direto na linha de comando** (fora de
> heredoc) e com confirmação explícita das imagens.

```bash
umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${NEW_VERSION}/" .env > .env.new
grep -n "^SIRHOSP_VERSION=${NEW_VERSION}$" .env.new
```

Se habilitando o token agora, acrescente-o antes de promover o `.env`
(substitua `<TOKEN-GERADO>`; nada a fazer para subir fail-closed):

```bash
grep -q "^SIRHOSP_UPSTREAM_API_TOKEN=" .env.new \
  || printf '\nSIRHOSP_UPSTREAM_API_TOKEN=%s\n' "<TOKEN-GERADO>" >> .env.new
grep -c "^SIRHOSP_UPSTREAM_API_TOKEN=.\{32,\}$" .env.new   # 1 (>= 32 bytes)
```

```bash
chmod 600 .env.new && mv .env.new .env
mv ${COMPOSE_FILE}.new $COMPOSE_FILE
docker compose --env-file .env -f $COMPOSE_FILE config --quiet
docker compose --env-file .env -f $COMPOSE_FILE pull
docker compose --env-file .env -f $COMPOSE_FILE run --rm web \
  uv run --no-sync python manage.py migrate --noinput  # no-op esperado
```

Direto na linha de comando:

```bash
docker compose --env-file .env -f compose.hospital.yml up -d --remove-orphans \
  --scale persistent_worker=10 db web persistent_worker summary_worker
install -m 0644 deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/
systemctl daemon-reload
docker compose --env-file .env -f compose.hospital.yml ps --format '{{.Name}} {{.Image}}' | sort
```

Critério: 12 containers na imagem rc.49; `migrate` sem migrations novas.

## Validação antes de retomar produtores

```bash
docker compose --env-file .env -f $COMPOSE_FILE ps
docker compose --env-file .env -f $COMPOSE_FILE exec -T web \
  uv run --no-sync python manage.py check

health_host="$(grep -E "^DJANGO_ALLOWED_HOSTS=" .env | cut -d= -f2- | cut -d, -f1)"
host_port="$(grep -E "^DJANGO_PORT=" .env | cut -d= -f2-)"
curl -fsS -H "Host: ${health_host}" "http://127.0.0.1:${host_port}/health/"; echo
for path in painel/ painel/altas/ altas/ reconciliacao/ beds/ statistics/ pendencias/ metrica-ingestao/; do
  code=$(curl -sS -o /dev/null -w '%{http_code}' -H "Host: ${health_host}" \
    "http://127.0.0.1:${host_port}/${path}")
  echo "$path $code"
done
code=$(curl -sS -o /dev/null -w '%{http_code}' -H "Host: ${health_host}" \
  "http://127.0.0.1:${host_port}/api/v1/inpatients/current")
echo "api/v1/inpatients/current $code"
```

Critérios: containers rc.49 sem crash loop, `check` sem issues, `/health/`
ok, rotas autenticadas `302` e, em `/api/v1/inpatients/current`:

- **500** — deploy fail-closed (token vazio): prova a API wired e fechada;
- **401** — token configurado e chamada sem credencial: prova a autenticação
  ativa.

Qualquer outro código (302/404) indica problema de rota/middleware: pare e
reporte. Com token configurado, a chamada autorizada
(`Authorization: Bearer $SIRHOSP_UPSTREAM_API_TOKEN`) deve responder `200`
com a foto do último ciclo concluído (`cycle_seq`, `row_count`); confira o
corpo apenas de forma agregada (contagens), sem expor dados de pacientes no
terminal.

## Rollback

Somente imagem: a rc.48 está totalmente funcional. Não há migration para
reverter; o token (se configurado) pode permanecer no `.env` — a rc.48 não lê
a variável. Pare produtores, drene, troque `SIRHOSP_VERSION=v0.1.0-rc.48`
e recrie os containers com o Compose `compose.hospital.yml.v0.1.0-rc.48`
(o asset rc.48 não passa o token, mas isso é inócuo); o `migrate` da rc.48
é no-op.
