# Runbook de Upgrade — v0.1.0-rc.22 (2026-09-06)

## Escopo

Implementa a ADR-0010 / change `orchestrate-d1-exit-recovery`: o
**orquestrador adaptativo** passa a executar a recuperação D-1 de saídas
**in-process** na janela silenciosa `[01:00, 05:00)` `America/Bahia`,
imediatamente antes de abrir o próximo ciclo, quando o loop está elegível
(fila drenada e nenhum batch aberto). Uma tentativa por data local (flag em
memória, avançada antes da tentativa); falha do D-1 **nunca bloqueia** o
ciclo de censo (`except (Exception, SystemExit)` com log agregado); o
runtime S11, o scheduler manual e os timers `:13`/`:47` seguem intocados.

- Base do upgrade: **v0.1.0-rc.21** (produção em `7816bf5`).
- Intervalo da release: commits `14781f9` (ADR-0010) e `876684d` (slice
  ODER-S1: `apps/census/orchestration.py` + testes; 19 casos novos, suíte
  unit **3557**).
- **Nenhuma migration** (schema rc.21 == schema rc.22): o passo D-1 não
  cria persistência nova.

## Timer D-1

O `sirhosp-historical-recovery.timer` (05:00) foi **desabilitado** em
produção em 2026-09-06 (incidente de contenção: as seis tentativas do
scheduler falharam com exit 75 contra batches de ~1000 runs). O scheduler
`exit-reconciliation-scheduler.sh` permanece como caminho **manual** (D-1
pontual, catch-up, hourly). Os timers `:13`/`:47` permanecem inertes —
habilitação continua decisão operacional separada.

## Procedimento

1. Preferir uma janela entre ciclos do orquestrador (fila drenada), mas o
   upgrade é um recreate simples: um run de censo interrompido vira órfão
   recuperável pelo stale recovery padrão (recriado pelo ciclo seguinte).
2. Atualizar `.env` (modo 600): `SIRHOSP_VERSION=v0.1.0-rc.22`.
3. Aplicar: `docker compose --env-file .env -f compose.hospital.yml up -d`
   (recreate da topologia na nova imagem; **sem migrate** — segunda
   execução não é necessária; `showmigrations` permanece idêntico ao
   rc.21).
4. Verificar: `docker compose ps` (14 containers, rc.22),
   `manage.py check` sem issues, health `check_ingestion_pipeline_health`
   sem novas violações, `systemctl is-enabled
   sirhosp-historical-recovery.timer`
   → `disabled`.
5. **Rollback**: sem migrations, o rollback é o redeploy imediato da
   rc.21 (reverter `SIRHOSP_VERSION` + `up -d`). O passo D-1 da madrugada
   entre deploy e rollback, se executado, é inofensivo (runtime
   idempotente por data; eventos append-only com latest-reconciled-wins).

## Gate pós-deploy: primeira noite orquestrada

Na janela `[01:00, 05:00)` `America/Bahia` seguinte:

- `docker compose logs census_orchestrator | grep "Quiet-window D-1"`
  deve exibir início e fim com data local e duração;
- eventos de reconciliação criados para a data D-1
  (`ReconciliationEvent` agregado por status — consulta somente contagens);
- `report_admission_reconciliation_integrity` sem novas violações
  estruturais (o mapa do legado permanece);
- se o passo D-1 **não** disparar (ex.: fila nunca drenou na janela),
  registrar e usar o scheduler manual como fallback; investigar o motivo
  da contenção antes de reabrir a questão do timer.

## Invariantes preservados

- Credenciais fora de argv (passo in-process herda o env do anchor
  Playwright — `ps -ef` segue limpo);
- saída agregada nos logs (data/duração/tipo de exceção apenas);
- sem `--apply`, requeue, backfill ou timer novo neste deploy;
- `systemctl list-timers 'sirhosp-*'` segue com apenas
  `sirhosp-ingestion-health.timer`.
