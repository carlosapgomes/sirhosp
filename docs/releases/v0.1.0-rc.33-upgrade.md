# Runbook de Upgrade — v0.1.0-rc.33 (2026-09-29)

## Escopo

Esta release entrega o change `link-statistics-patients-to-admissions`
(1 slice vertical LSPA-S1): **navegação nominal no relatório diário de
estatísticas**.

- cada linha nominal das listas do relatório diário em `/statistics/`
  (entradas, saídas, eventos com origem ou destino não identificado e
  pacientes do fechamento, incluindo as listas da seção
  `Setor não identificado`) torna-se clicável e abre a página de internações
  do paciente (`/patients/<pk>/admissions/`) quando o prontuário resolve
  para exatamente um paciente;
- prontuário sem candidato único (ausente ou ambíguo entre sistemas de
  origem distintos) aponta para a busca de pacientes filtrada pelo
  prontuário (`/patients/?q=<prontuario>`), no padrão de `/beds/`; linha sem
  prontuário permanece texto simples;
- a resolução ocorre em tempo de leitura na projeção do relatório, em uma
  única query adicional por render quando há prontuários nominais, sem
  N+1; nada é persistido;
- revisões materializadas, impressão digital (`source_fingerprint`),
  exportação XLSX (seções, colunas, valores e ordenação), permissões e
  `Cache-Control` permanecem inalterados.

Base do upgrade: **v0.1.0-rc.32** (`f51653f`).

O intervalo `v0.1.0-rc.32..rc.33` altera apenas código de aplicação, template
e testes (`apps/statistics_reports/presentation.py`,
`apps/statistics_reports/templates/statistics_reports/daily_report.html` e os
dois arquivos de teste de integração correspondentes), além de registros de
estado de tarefas e do arquivamento do change. **Nenhuma migration** é
adicionada ou removida (`makemigrations --check --dry-run` limpo). **Nenhuma
variável de ambiente nova** e nenhuma credencial nova. O Compose e todos os
assets de runtime são **byte a byte idênticos aos da RC32**; SHA-256 do
Compose: `cd0e444c9316a8b267823f31cf1d4a1fee40e7bf2b96b9aa27da10002f4f9dc1`.

Validação anterior à tag:

- `./scripts/test-in-container.sh quality-gate` (check, unit, ruff, mypy) —
  exit 0;
- `./scripts/test-in-container.sh integration` — 904 aprovados;
- suíte focada do slice (página + exportação) — 73 aprovados, com RED/GREEN
  documentado em `/tmp/sirhosp-slice-LSPA-S1-report.md`;
- `uv run python manage.py makemigrations --check --dry-run` — nenhuma
  mudança detectada;
- `./scripts/markdown-lint.sh` — sem erros;
- `openspec validate` estrito do change (pré-arquivamento) e das specs
  canônicas (pós-arquivamento).

## Impacto operacional

- Release somente de código, template e testes.
- Nenhuma migration, alteração de schema, variável de ambiente ou permissão.
- Nenhuma alteração em materialização, pipeline adaptativo, workers, timers,
  units ou Compose.
- O render do relatório diário executa uma query adicional de resolução
  (varredura por `patient_source_key__in`, sem índice isolado na coluna —
  mesmo perfil da lista de `/beds/` hoje); monitorar latência se a tabela de
  pacientes crescer. Degradação fail-safe: ambiguidade ou prontuário não
  encontrado caem para o link de busca, nunca para um paciente errado.
- A exportação XLSX continua consumindo a mesma projeção com os mesmos
  campos fixos; nenhum valor derivado da resolução entra no workbook.
- O rollback de imagem não exige desfazer migrations.

## Pré-condições

1. Confirmar que a versão atual é `v0.1.0-rc.32` sem imprimir outras variáveis
   do `.env`.
2. Confirmar PostgreSQL saudável.
3. Registrar a escala atual de `persistent_worker`; o baseline hospitalar é de
   10 réplicas.
4. Parar temporariamente os produtores de novos ciclos (`census_orchestrator`
   e `sirhosp-stale-reconciliation.timer`), mantendo os workers ativos para
   drenar a fila.
5. Aguardar `IngestionRun` sem itens `queued` ou `running` e nenhum batch de
   censo aberto (mesma checagem de drenagem da seção 5c do `deploy/README.md`).
6. Baixar da release imutável o Compose, os units e este runbook (assets
   idênticos aos da RC32; o download pela tag da RC33 mantém a procedência
   byte a byte de uma única tag).
7. Criar backup PostgreSQL em formato custom, confirmar arquivo não vazio e
   validar o catálogo com `pg_restore --list`.
8. Confirmar que os três timers de fallback (`sirhosp-discharges.timer`,
   `sirhosp-historical-recovery.timer` e `sirhosp-daily-statistics.timer`)
   estão `disabled` e `inactive`.

## Download e backup

```bash
set -euo pipefail
export OLD_VERSION=v0.1.0-rc.32
export NEW_VERSION=v0.1.0-rc.33
export COMPOSE_FILE=compose.hospital.yml
cd /srv/apps/prisma

mkdir -p backups deploy/systemd
chmod 700 backups

curl -fL --retry 3 -o "${NEW_VERSION}-upgrade.md.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${NEW_VERSION}-upgrade.md"
curl -fL --retry 3 -o "${COMPOSE_FILE}.new" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${COMPOSE_FILE}"

# Assets de runtime inalterados desde a RC32; instalados da MESMA tag da
# imagem para manter a procedência byte a byte.
curl -fL --retry 3 -o deploy/exit-reconciliation-scheduler.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/exit-reconciliation-scheduler.sh"
curl -fL --retry 3 -o deploy/daily-statistics-activation-preflight.sh \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/daily-statistics-activation-preflight.sh"
chmod +x deploy/exit-reconciliation-scheduler.sh deploy/daily-statistics-activation-preflight.sh
for unit in \
  sirhosp-discharges.service sirhosp-discharges.timer \
  sirhosp-historical-recovery.service sirhosp-historical-recovery.timer \
  sirhosp-stale-reconciliation.service sirhosp-stale-reconciliation.timer \
  sirhosp-daily-statistics.service sirhosp-daily-statistics.timer; do
  curl -fL --retry 3 -o "deploy/systemd/${unit}" \
    "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${unit}"
done

sha256sum "${COMPOSE_FILE}.new"
# esperado: cd0e444c9316a8b267823f31cf1d4a1fee40e7bf2b96b9aa27da10002f4f9dc1
cp -p "$COMPOSE_FILE" "${COMPOSE_FILE}.${OLD_VERSION}"
mv "${NEW_VERSION}-upgrade.md.new" "${NEW_VERSION}-upgrade.md"

backup_path="backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
docker compose --env-file .env -f "$COMPOSE_FILE" exec -T db \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' \
  > "${backup_path}"
test -s "${backup_path}"
docker compose --env-file .env -f "$COMPOSE_FILE" exec -T db \
  pg_restore --list < "${backup_path}" >/dev/null
printf 'backup=%s bytes=%s validated=1\n' "${backup_path}" "$(stat -c %s "${backup_path}")"
```

## Upgrade

```bash
set -euo pipefail
cd /srv/apps/prisma
export NEW_VERSION=v0.1.0-rc.33
export COMPOSE_FILE=compose.hospital.yml

umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${NEW_VERSION}/" .env > .env.new
grep -n "^SIRHOSP_VERSION=${NEW_VERSION}$" .env.new
chmod 600 .env.new
mv .env.new .env
mv "${COMPOSE_FILE}.new" "${COMPOSE_FILE}"

docker compose --env-file .env -f "$COMPOSE_FILE" config --quiet
docker compose --env-file .env -f "$COMPOSE_FILE" pull
docker compose --env-file .env -f "$COMPOSE_FILE" run --rm web \
  uv run --no-sync python manage.py migrate --noinput
docker compose --env-file .env -f "$COMPOSE_FILE" \
  up -d --remove-orphans --scale persistent_worker=10 \
  db web persistent_worker summary_worker

# Units da MESMA tag instalados sem habilitar nem iniciar nada.
sudo install -m 0644 deploy/systemd/*.service deploy/systemd/*.timer /etc/systemd/system/
systemctl daemon-reload
for timer in sirhosp-discharges.timer sirhosp-historical-recovery.timer sirhosp-daily-statistics.timer; do
  printf 'legacy_timer_state=%s enabled=%s active=%s\n' "${timer}" \
    "$(systemctl is-enabled "${timer}" || true)" \
    "$(systemctl is-active "${timer}" || true)"
done
```

Como não há migration nova, `migrate --noinput` é um no-op de schema. O
`census_orchestrator` permanece parado durante os primeiros smokes.

## Rollback

Como não há migration nova, o rollback é somente de imagem e Compose. Pare os
produtores e drene novamente a fila antes de recriar os workers se o sistema
já tiver retomado o processamento.

```bash
set -euo pipefail
cd /srv/apps/prisma
export OLD_VERSION=v0.1.0-rc.32
export COMPOSE_FILE=compose.hospital.yml

systemctl stop sirhosp-stale-reconciliation.timer
docker compose --env-file .env -f "$COMPOSE_FILE" stop census_orchestrator

umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${OLD_VERSION}/" .env \
  > .env.rollback
chmod 600 .env.rollback
mv .env.rollback .env
cp "${COMPOSE_FILE}.${OLD_VERSION}" "$COMPOSE_FILE"

docker compose --env-file .env -f "$COMPOSE_FILE" config --quiet
docker compose --env-file .env -f "$COMPOSE_FILE" pull
docker compose --env-file .env -f "$COMPOSE_FILE" \
  up -d --remove-orphans --scale persistent_worker=10 \
  db web persistent_worker summary_worker
```

Valide a RC32 antes de reativar o orquestrador e o timer. O backup PostgreSQL
é uma salvaguarda operacional e não deve ser restaurado neste rollback
code-only. Pare e investigue antes de qualquer restauração de banco.
