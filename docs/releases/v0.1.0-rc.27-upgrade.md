# Runbook de Upgrade — v0.1.0-rc.27 (2026-09-08)

## Escopo

Entrega o primeiro slice do change
`show-captured-patient-exits-on-dashboard`:

- `/painel/altas/` passa a mostrar somente saídas efetivas capturadas por
  `DischargeRecord.saida_em`;
- registros entram no indicador independentemente do status de reconciliação;
- o eixo contém os dias consecutivos do período até ontem, preenchendo com zero
  datas sem saída;
- SMA-7, EMA-7, SMA-30, médias por dia da semana e cores de fim de semana usam a
  mesma série;
- distribuição horária e resumo por especialidade usam a hora de `saida_em` em
  `America/Bahia`;
- a série de sumários por `alta_em` deixa o gráfico principal.

Base do upgrade: **v0.1.0-rc.26** (`9a77745`).

Validação do release:

- 3.587 testes unitários;
- 680 testes de integração;
- Django check, Ruff e mypy;
- quality gate oficial em container;
- OpenSpec estrito e Markdown lint.

## Impacto operacional

- Release somente de código e template.
- Nenhuma migration, alteração de schema ou nova variável de ambiente.
- Nenhuma alteração em `DailyDischargeCount`, reconciliação, backfill, workers,
  timers ou systemd.
- O deploy não executa backfill nem reprocessa dados clínicos.
- A contagem histórica é calculada diretamente dos registros de saída já
  persistidos.

## Pré-condições

1. Confirmar que a versão atual é `v0.1.0-rc.26` sem imprimir outras variáveis
   do `.env`.
2. Confirmar PostgreSQL saudável.
3. Aguardar `IngestionRun` sem itens `queued` ou `running` antes de recriar os
   workers.
4. Registrar a escala atual de `persistent_worker`; o baseline hospitalar deste
   upgrade é 10 réplicas.
5. Baixar da release imutável o Compose e este runbook.
6. Criar backup PostgreSQL em formato custom e confirmar arquivo não vazio.

## Procedimento

No host `eon`, em `/srv/apps/prisma`:

```bash
export OLD_VERSION=v0.1.0-rc.26
export NEW_VERSION=v0.1.0-rc.27

curl -fL \
  -o "${NEW_VERSION}-upgrade.md" \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/${NEW_VERSION}-upgrade.md"
curl -fL \
  -o compose.hospital.yml.new \
  "https://github.com/carlosapgomes/sirhosp/releases/download/${NEW_VERSION}/compose.hospital.yml"

cp compose.hospital.yml "compose.hospital.yml.${OLD_VERSION}"
mkdir -p backups
chmod 700 backups
docker compose --env-file .env -f compose.hospital.yml up -d db
docker compose --env-file .env -f compose.hospital.yml exec -T db \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" --format=custom' \
  > "backups/sirhosp-$(date -u +%Y%m%dT%H%M%SZ).dump"
test -s "$(ls -1t backups/sirhosp-*.dump | head -1)"

umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${NEW_VERSION}/" .env \
  > .env.new
chmod 600 .env.new
mv .env.new .env
mv compose.hospital.yml.new compose.hospital.yml

docker compose --env-file .env -f compose.hospital.yml config --quiet
docker compose --env-file .env -f compose.hospital.yml pull
docker compose --env-file .env -f compose.hospital.yml run --rm web \
  uv run --no-sync python manage.py migrate --noinput
docker compose --env-file .env -f compose.hospital.yml \
  up -d --remove-orphans --scale persistent_worker=10
```

Critérios de aceite:

- web saudável e `/health/` responde com sucesso;
- `/painel/altas/` responde com redirecionamento para login quando não
  autenticado;
- 10 réplicas de `persistent_worker` estão ativas;
- web, workers, orquestrador e worker de sumários usam a tag exata
  `v0.1.0-rc.27`;
- logs recentes não apresentam crash loop ou erro de migration.

## Rollback

Como não há migration, o rollback é somente de imagem e Compose:

```bash
export OLD_VERSION=v0.1.0-rc.26
umask 077
sed "s/^SIRHOSP_VERSION=.*/SIRHOSP_VERSION=${OLD_VERSION}/" .env \
  > .env.rollback
chmod 600 .env.rollback
mv .env.rollback .env
cp "compose.hospital.yml.${OLD_VERSION}" compose.hospital.yml

docker compose --env-file .env -f compose.hospital.yml config --quiet
docker compose --env-file .env -f compose.hospital.yml pull
docker compose --env-file .env -f compose.hospital.yml \
  up -d --remove-orphans --scale persistent_worker=10
curl -fsS http://127.0.0.1:8000/health/
```

O backup PostgreSQL é uma salvaguarda operacional e não deve ser restaurado para
este rollback code-only. Pare e investigue antes de qualquer restauração de
banco.
